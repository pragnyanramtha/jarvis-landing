01 — The loop

Four steps, no tab to switch.

No orchestrator layer, no five agents taking turns. One loop, fast enough that talking feels faster than typing.

01

Wake

Say “Hey Jarvis.” Detection runs on-device, so it works with the lid closed on your network.

02

Listen

Streaming speech-to-text starts the moment you do. You can talk over it and correct yourself.

03

Act

The agent reads, greps, writes, and runs commands against your real repo — fail-closed on anything destructive.

04

Answer

It speaks back what it did, in under a second, and waits for the next instruction.

02 — What it actually does

Boring tools. Serious memory.

Six tools and two memory stores. Deliberately unglamorous — the value is in the loop being reliable, not the feature list being long.

01

Terminal, not a chat windowbash · read · write · grep · glob · git

Your interactive shell and the agent's shell are separate surfaces. You keep your prompt; it gets its own sandboxed tool call.

02

Memory you can readmemory.md + sqlite

A bounded Markdown file for what matters long-term, plus a searchable store of past episodes. Both are plain files on disk. No black box, nothing to export.

03

Every session replayablestructured json logs

Each run writes a timeline, a transcript, and a metrics file. When the agent does something odd, you can read exactly what it saw.

04

Skills it writes itself~/.jarvis/skills

After it gets something right twice, it saves the procedure as a skill and searches for it next time. Versioned in a single index file.

05

Graceful when keys are missingfeature flags

No API key means that capability turns off, not that the app breaks. Run the whole loop today with a deterministic stub model and zero secrets.

06

Bring your own modelsopenrouter · any model

Point it at whichever model you already pay for. Swap the voice, the model, or both without touching the agent loop.

03 — Where your code goes

Nowhere it didn't have to.

An agent with shell access deserves a straight answer, so here's the whole architecture in three lines.

Localhost only

The sidecar binds to 127.0.0.1 and demands a handshake token before it accepts a single command.

Your keys, your machine

Nothing is proxied through us. Voice, models, and transcripts stay on hardware you control.

Nothing hidden

Full logs on disk, readable by you. If it's doing something you can't audit, you shouldn't run it.
